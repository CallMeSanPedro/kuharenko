# Минимальная ресурсная модель

Склад телеком-оборудования и расходных материалов.

Два слоя:

1. **Справочники** — записи «ключ → значение». Запись может ссылаться на запись другого справочника. Ссылка — **контекст**.
2. **Ресурсы** — дерево от более абстрактного узла к более конкретному. Глубина не ограничена.

Процессов нет: приход, перемещение, остаток, статус. Кода нет.

## Обязательный состав

Приложение держится на трёх справочниках и двух корневых ресурсах. Остальные справочники и узлы добавляются позже и на это ядро не влияют.

### Справочники

| code | name | контекст | зачем без него нет склада |
| --- | --- | --- | --- |
| manufacturer | Производитель | — | модель некуда привязать |
| model | Модель | manufacturer | оборудованию нечем отличаться как номенклатуре |
| uom | Единица измерения | — | нельзя отличить штуку от метра |

Обязательная запись одна: `uom / pcs → шт`. Корень «Оборудование» ссылается на неё.

Записи `manufacturer` и `model` на старте могут быть пустыми. Каталог наполняется данными, не установкой.

`uom / m → м` нужен кабелю и волокну, но появляется вместе с первой позицией в метрах.

### Ресурсы

Два корня. У обоих `parent` пуст. Третьего корня нет: любая новая позиция — потомок одного из них.

| name | что задаёт сам | что задают потомки |
| --- | --- | --- |
| Оборудование | контекст `uom = pcs` | модель, затем атрибуты спецификации, затем `serial_number` |
| Расходный материал | имя корня | `uom` конкретной позиции, спецификацию; модель по необходимости |

`uom` висит на корне оборудования, потому что каждая единица оборудования учитывается в штуках. У расходного материала единицы разные, поэтому `uom` ставит потомок, который впервые становится позицией.

### Когда узел уже можно хранить

Роли вычисляются по цепочке. Отдельных видов узла под них нет.

**Позиция оборудования** — потомок «Оборудования», в эффективном контексте есть `model`. Производитель читается из модели. `uom = pcs` уже пришёл от корня.

**Экземпляр** — потомок такой позиции с атрибутом `serial_number`. Значение уникально среди всех ресурсов.

**Позиция расходного материала** — потомок «Расходного материала», в эффективном контексте есть `uom`. Модель для неё необязательна.

Между корнем и этими ролями может быть сколько угодно промежуточных узлов.

## Справочник

Справочник — набор записей. Значение записи — строка.

У справочника не больше одного справочника-контекста. Цепочка контекстов любой длины: ревизия → модель → производитель. Цикл запрещён.

Контекст — ссылка, не копия.

### Dictionary

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| code | стабильный код справочника |
| name | название |
| contextDictionaryId | справочник-контекст, либо пусто |

### DictionaryEntry

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| dictionaryId | справочник записи |
| key | ключ, уникален внутри справочника |
| value | значение, строка |
| contextEntryId | запись справочника-контекста, либо пусто |

### Правила

1. Если у справочника задан `contextDictionaryId`, у каждой записи `contextEntryId` обязателен и принадлежит этому справочнику.
2. Если контекст справочника пуст, `contextEntryId` пуст.
3. Цепочка контекстов справочников без циклов и без предела глубины.
4. Ключ уникален внутри своего справочника.
5. Справочники `manufacturer`, `model`, `uom` существуют всегда. `model.contextDictionaryId` указывает на `manufacturer`.

### Пример записей

Записи ниже иллюстрация, не обязательный состав. Обязательна только `pcs`.

```
manufacturer
  huawei  → Huawei
  corning → Corning

model                  контекст
  ma5800   → MA5800    huawei
  sm-9-125 → SM 9/125  corning

uom
  pcs → шт
  m   → м
```

## Ресурс

Ресурс — один вид узла. Узел может иметь родителя. Родитель — более абстрактный ресурс. Дети — более конкретные.

Корень: `parent` пуст. Таких узла ровно два: «Оборудование» и «Расходный материал». У узла сколько угодно детей. Длина пути от корня не ограничена.

Узел хранит только своё дополнение. Эффективные контекст и атрибуты не копируются и не лежат на потомке. Они считаются по цепочке от корня до узла.

Потомок видит правку предка сразу.

### Resource

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| parentId | родитель, либо пусто у корня |
| name | имя этого узла |
| code | артикул, необязателен; если задан — уникален среди всех ресурсов |

Имя и артикул не наследуются. Наследуются контекст и атрибуты.

### Что узел добавляет

**Контекст** — ссылки на записи справочников, введённые на этом узле.

| Поле | Смысл |
| --- | --- |
| resourceId | узел |
| dictionaryId | справочник |
| entryId | запись этого справочника |

**Атрибут** — свободная пара, введённая на этом узле.

| Поле | Смысл |
| --- | --- |
| resourceId | узел |
| key | код атрибута |
| value | строка |

Серийный номер — атрибут `serial_number`. Его вводит экземпляр. Узел может добавить и другие ключи: `lot`, `length_m`, `wavelength_nm`.

### Эффективное значение

Для узла `R` с предками от корня `P0 … Pn`, `R`:

- эффективный контекст = объединение прямых контекстов `P0 … R`
- эффективные атрибуты = объединение прямых атрибутов `P0 … R`

Справочный контекст дальше читается по справочникам. Ресурс со ссылкой на модель `ma5800` имеет производителя `huawei`, потому что контекст записи модели — `huawei`. Производитель на ресурс вторым прямым контекстом не копируется.

### Правила цепочки

1. `parentId` пуст только у «Оборудования» и «Расходного материала». Дальше цепочка без циклов. Глубина и число детей не ограничены.
2. Дополнение, не замена. Потомок не занимает справочник, который уже есть в эффективном прямом контексте предка. Потомок не повторяет ключ атрибута предка.
3. На одном узле один справочник — одна запись. Один ключ атрибута — одно значение.
4. Прямой контекст не указывает справочник, который уже достижим обходом контекста справочников от другой прямой ссылки того же эффективного контекста. Модель указана — производитель берётся из модели. Прямая ссылка на производителя допустима на узле, где модели ещё нет. Потомок, который добавляет модель, выбирает модель этого производителя.
5. `serial_number` встречается только у потомка «Оборудования». На пути от корня до этого узла уже есть `model`. Значение `serial_number` уникально среди всех ресурсов.
6. Узел с детьми не удаляется. Два корня не удаляются.

## Примеры

Оборудование. Корень обязательный, узлы под ним произвольные.

```
Оборудование                      корень, uom = pcs

  └─ Оптический модуль
       attributes: domain = optical

       └─ SFP+
            attributes: form_factor = SFP+

            └─ SFP+ 10G LR          позиция: появилась model
                 context:    model = sfp-10g-lr-hw
                             manufacturer читается из модели → huawei
                 attributes: rate = 10G
                             wavelength_nm = 1310
                             reach_km = 10

                 └─ экземпляр
                      attributes: serial_number = HW192837465
```

Эффективно у экземпляра: `uom=pcs`, модель `sfp-10g-lr-hw`, производитель Huawei через модель, атрибуты `domain`, `form_factor`, `rate`, `wavelength_nm`, `reach_km`, `serial_number`.

Рядом от `SFP+` может выходить другая ветка `SFP+ 10G SR` со своей моделью.

Расходник. Корень обязательный. `uom` и модель появляются ниже.

```
Расходный материал                корень

  └─ Патчкорд                      позиция: uom = pcs
       └─ SM LC-LC 3м
            context:    model = patch-sm-lc-lc
            attributes: fiber = SM
                        connector = LC-LC
                        length_m = 3
```

Кабель в метрах — потомок того же корня, на своей позиции `uom = m`. Количества в этой модели нет.

## Инварианты

1. Существуют справочники `manufacturer`, `model`, `uom`. Контекст `model` — `manufacturer`. В `uom` есть запись `pcs`.
2. Существуют корни «Оборудование» (`uom = pcs`) и «Расходный материал». Других корней нет.
3. Контекст записи справочника принадлежит справочнику-контексту. Цепочка справочников без цикла.
4. Прямой контекст ресурса принадлежит заявленному справочнику.
5. Эффективные контекст и атрибуты узла — объединение добавлений по предкам и себе.
6. По цепочке справочник и ключ атрибута встречаются не больше одного раза.
7. Производитель модели читается по контексту записи модели.
8. `serial_number` только под «Оборудованием», ниже уже заданной `model`, и уникален глобально.
9. Родительская цепочка ресурсов без цикла.

## Вне модели

- Склад, ячейка, документ, количество, резерв, статус.
- Состав «шасси содержит плату». Это другая связь, не родитель абстракции.
- Каталог допустимых ключей атрибутов. Ключ пока свободная строка.
- Конкретные производители, модели и промежуточные ветки вроде «SFP+». Это данные каталога, не каркас приложения.
