# Минимальная ресурсная модель

Склад телеком-оборудования и расходных материалов.

Два слоя:

1. **Справочники** — записи «ключ → значение». У записи сколько угодно контекстных ссылок. Ссылка ведёт на запись справочника или на ресурс.
2. **Ресурсы** — дерево от более абстрактного узла к более конкретному. Глубина не ограничена. Ресурс ссылается на записи справочников и сам бывает контекстом записи справочника.

Процессов нет: приход, перемещение, остаток, статус. Кода нет.

Оборудование и расходный материал для склада — одна учётная единица. Общие поля у них одни: код учёта, имя, единица измерения, модель по необходимости, атрибуты спецификации. Модуль и патчкорд отличаются наполнением этой единицы и тем, есть ли под ней физический потомок.

## Обязательный состав

Приложение держится на трёх справочниках и на ресурсе с заполненным `sku`. Именованных корней нет.

### Справочники

| code | name | зачем без него нет склада |
| --- | --- | --- |
| manufacturer | Производитель | модели не на что сослаться как на производителя |
| model | Модель | номенклатуре с моделью нечем назваться |
| uom | Единица измерения | учётной единице не в чем считаться |

Записи всех трёх на старте могут быть пустыми. Первая учётная единица требует одну запись `uom`: штука, метр или любая другая. `manufacturer` и `model` заполняются, когда у SKU появляется модель.

У записи `model` среди контекстов обычно есть запись `manufacturer`. Это обычная ссылка, не предел: у той же записи могут быть ещё ссылки на другие записи и на ресурсы.

### SKU

`sku` — код учётной единицы на узле ресурса. Узел с заполненным `sku` и есть то, что склад учитывает.

Общее у каждой учётной единицы:

| что | правило |
| --- | --- |
| sku | свой код, уникален среди всех ресурсов |
| name | имя этого узла |
| uom | есть в эффективном контексте |
| model | в эффективном контексте, если у позиции есть модель; производитель находится среди контекстов этой модели |
| атрибуты | спецификация, накопленная по цепочке до этого узла включительно |

`uom` и `model` могут стоять на самом SKU или на предке. На SKU они уже обязаны сложиться в эффективный контекст: `uom` всегда, `model` когда она есть у этой позиции.

Предки SKU — группы без своего кода учёта. Потомки SKU своего `sku` не имеют: это уточнение той же учётной единицы. Серийный номер — атрибут `serial_number` такого потомка. Значение уникально среди всех ресурсов. Учётная единица без таких потомков остаётся одной позицией склада: патчкорд, кабель, крепёж.

Если уточнение должно учитываться отдельно, это соседний узел со своим `sku`, а не ребёнок текущего.

На одном пути от корня до узла `sku` встречается не больше одного раза.

### Почему SKU не справочник

Справочник хранит значение, которое переиспользуют. Производитель нужен многим моделям. Модель нужна многим учётным единицам. Единица измерения нужна каждому SKU. Запись справочника — ключ, одна строка и набор контекстных ссылок. Своей цепочки атрибутов у записи нет, потомков с серийным номером нет.

SKU называет один узел ресурса. Этот узел уже собрал эффективный контекст и атрибуты предков. Под ним висят физические потомки той же учётной единицы, и они читают эту спецификацию по цепочке. Код учёта — идентификатор узла. Запись справочника может ссылаться на этот узел как на контекст, но сам SKU от этого записью справочника не становится.

Одна модель `sfp-10g-lr-hw` может стоять на нескольких SKU, если склад считает их раздельно. Модель при этом остаётся записью справочника. Различие SKU живёт атрибутами и местом узла в дереве ресурса. В справочник это не свернуть: у записи нет наследования атрибутов и нет потомка с `serial_number`.

### На каком срезе появляется

Глубина числом не задана. `sku` ставится на узле, который и есть единица складского учёта.

Выше него абстракция: общие атрибуты нескольких будущих SKU. Такой узел ещё не отвечает, что именно принимают и считают отдельной строкой.

Сам узел с `sku` — самый конкретный ресурс, который всё ещё описывает класс взаимозаменяемых позиций. К этому месту в эффективном контексте уже есть `uom`, и собраны все атрибуты, из-за которых эту строку склада не сливают с соседней. Модель, если она у позиции есть, тоже уже здесь.

Ниже физика той же учётной единицы: серийный номер, партия. Эти узлы своего `sku` не получают. `HW192837465` — один экземпляр `SFP-10G-LR`, а не новая номенклатура.

Патчкорд без серийных потомков заканчивается на этом же срезе: лист с `sku` и есть учётная единица.

## Справочник

Справочник — набор записей. Значение записи — строка.

Контекст записи — ссылка, не копия. Ссылок у одной записи сколько угодно, в том числе ноль. Каждая ссылка указывает на запись любого справочника или на ресурс. Один и тот же ресурс может быть контекстом многих записей. Одна запись может ссылаться на несколько ресурсов и на несколько записей сразу.

Справочник как тип контекст не объявляет. Ссылки живут на записях.

### Dictionary

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| code | стабильный код справочника |
| name | название |

### DictionaryEntry

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| dictionaryId | справочник записи |
| key | ключ, уникален внутри справочника |
| value | значение, строка |

### DictionaryEntryContext

| Поле | Смысл |
| --- | --- |
| entryId | запись, которой принадлежит ссылка |
| targetKind | `entry` или `resource` |
| targetId | запись справочника или ресурс |

Пара (`entryId`, `targetKind`, `targetId`) уникальна: одну и ту же цель дважды к одной записи не цепляют. На число разных целей предела нет.

### Правила

1. Цель `entry` — существующая запись справочника. Цель `resource` — существующий ресурс.
2. Ключ уникален внутри своего справочника.
3. Справочники `manufacturer`, `model`, `uom` существуют всегда.
4. Обход контекстов идёт по всем ссылкам записи. Ссылка на ресурс называет этот ресурс и на его предков сама не разворачивается.

### Пример записей

```
manufacturer
  huawei  → Huawei
  corning → Corning

model
  ma5800 → MA5800
    contexts: manufacturer/huawei
              resource SKU-MA5800-X17
  sm-9-125 → SM 9/125
    contexts: manufacturer/corning

uom
  pcs → шт
  m   → м

firmware
  v800r21 → V800R021
    contexts: model/ma5800
              resource SKU-MA5800-X17
              resource SKU-MA5800-X7
```

`firmware / v800r21` сразу показывает оба вида контекста: запись `model/ma5800` и два ресурса-шасси, на которых эта прошивка учитывается. Число ссылок схемы не ограничивает.

## Ресурс

Ресурс — один вид узла. Узел может иметь родителя. Родитель — более абстрактный ресурс. Дети — более конкретные.

Корень: `parent` пуст. Корней сколько угодно. У узла сколько угодно детей. Длина пути от корня не ограничена.

Узел хранит только своё дополнение. Эффективные контекст и атрибуты считаются по цепочке от корня до узла. На потомка они не копируются.

Потомок видит правку предка сразу.

Тот же узел может стоять в `DictionaryEntryContext` с `targetKind = resource`. Тогда он контекст записи справочника: прошивка, слот, комплектация ссылаются на него, а не копируют его имя.

### Resource

| Поле | Смысл |
| --- | --- |
| id | идентификатор |
| parentId | родитель, либо пусто у корня |
| name | имя этого узла |
| sku | код учётной единицы, необязателен; если задан — уникален среди всех ресурсов |

Имя и `sku` не наследуются. Наследуются контекст и атрибуты.

### Что узел добавляет

**Контекст** — ссылки на записи справочников, введённые на этом узле.

| Поле | Смысл |
| --- | --- |
| resourceId | узел |
| entryId | запись справочника |

**Атрибут** — свободная пара, введённая на этом узле.

| Поле | Смысл |
| --- | --- |
| resourceId | узел |
| key | код атрибута |
| value | строка |

Серийный номер — атрибут `serial_number` потомка узла с `sku`. Узел может добавить и другие ключи: `lot`, `length_m`, `wavelength_nm`.

### Эффективное значение

Для узла `R` с предками от корня `P0 … Pn`, `R`:

- эффективный контекст = объединение прямых контекстов `P0 … R`
- эффективные атрибуты = объединение прямых атрибутов `P0 … R`

Дальше читаются все контексты каждой связанной записи. У модели `ma5800` в контекстах есть `huawei` и ресурс `SKU-MA5800-X17`. Ресурс со ссылкой на эту модель видит оба. Производитель на ресурс отдельной копией не переносится.

Ссылка из записи на ресурс останавливается на этом ресурсе. Атрибуты ресурса в запись справочника не переносятся.

### Правила цепочки

1. `parentId` не создаёт цикл. Глубина и число детей не ограничены.
2. Дополнение, не замена. Потомок не занимает справочник, который уже есть в эффективном прямом контексте предка. Потомок не повторяет ключ атрибута предка.
3. На одном узле один справочник — одна запись. Один ключ атрибута — одно значение. У записи справочника такого предела нет: контекстов сколько угодно.
4. Узел с `sku` имеет `uom` в эффективном контексте. На пути от корня до узла не больше одного `sku`. Потомок узла с `sku` свой `sku` не задаёт.
5. `serial_number` задаётся у потомка узла с `sku`. Значение уникально среди всех ресурсов.
6. Узел с детьми не удаляется. Ресурс, на который есть контекстная ссылка записи, не удаляется.

## Примеры

Обе ветки — обычные ресурсы. Учёт начинается там, где заполнен `sku`.

```
Оптический модуль                 группа, sku пуст
  attributes: domain = optical

  └─ SFP+                         группа, sku пуст
       attributes: form_factor = SFP+

       └─ SFP+ 10G LR             учётная единица
            sku:        SFP-10G-LR
            context:    uom = pcs
                        model = sfp-10g-lr-hw
            attributes: rate = 10G
                        wavelength_nm = 1310
                        reach_km = 10

            └─ экземпляр          тот же sku, своего кода нет
                 attributes: serial_number = HW192837465
```

У экземпляра своего `sku` нет. Учётная единица находится обходом предков: `SFP-10G-LR`. Эффективно у экземпляра: `uom=pcs`, модель `sfp-10g-lr-hw`, все контексты этой модели, атрибуты `domain`, `form_factor`, `rate`, `wavelength_nm`, `reach_km`, `serial_number`.

Рядом от `SFP+` может стоять другая учётная единица `SFP-10G-SR` со своим `sku`.

Расходник — та же форма. Потомка с серийным номером нет.

```
Патчкорд                          группа, sku пуст

  └─ SM LC-LC 3м                  учётная единица
       sku:        PATCH-SM-LC-LC-3M
       context:    uom = pcs
                   model = patch-sm-lc-lc
       attributes: fiber = SM
                   connector = LC-LC
                   length_m = 3
```

Кабель в метрах — узел с собственным `sku` и `uom = m`. Количества в этой модели нет.

Запись справочника смотрит на ресурс, когда значение имеет смысл только рядом с этой учётной единицей:

```
firmware / v800r21
  contexts: model/ma5800
            resource SKU-MA5800-X17
            resource SKU-MA5800-X7
```

## Инварианты

1. Существуют справочники `manufacturer`, `model`, `uom`.
2. У записи справочника любое число контекстов. Цель каждой ссылки — запись справочника или ресурс.
3. Прямой контекст ресурса — запись справочника.
4. Эффективные контекст и атрибуты узла — объединение добавлений по предкам и себе. Контексты связанных записей читаются все.
5. По цепочке ресурса один справочник и один ключ атрибута встречаются не больше одного раза.
6. `sku` уникален глобально. На одном пути он один. У узла с `sku` в эффективном контексте есть `uom`.
7. `serial_number` стоит на потомке узла с `sku` и уникален глобально.
8. Родительская цепочка ресурсов без цикла.

## Вне модели

- Склад, ячейка, документ, количество, резерв, статус.
- Состав «шасси содержит плату». Это другая связь, не родитель абстракции.
- Каталог допустимых ключей атрибутов. Ключ пока свободная строка.
- Деление склада на оборудование и расходные материалы. Обе группы — учётные единицы с общим набором полей.
